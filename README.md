## Hello, I'm Cleopatra.

I build bespoke applications for real-world problems. Some began as tools we needed ourselves; each is shaped to become useful to more people.

Around this work, I say **we** deliberately. Building is collaboration. Ideas get sharper when more people use them, question them, test them, and add their own perspective.

## Why we build

Real-world problems are rarely one-size-fits-all. We build focused tools around specific needs, then invite the wider world to use, challenge, and improve them.

The work moves across media, creation, contextual reasoning, privacy, and safety. The applications are different, but the intent is consistent: make something useful, keep its claims honest, and leave the door open for others.

## Selected work

| Project | What it is | Current focus |
| --- | --- | --- |
| **Tazama** | An Africa-first place to discover authorized TV, films, series, radio, podcasts, sports, and first-party experiences, then enjoy them together. | Social media · voice · rights · privacy |
| **Ingia** | Private, on-device video recognition that identifies a transformed clip and opens the source film at the same moment. | Media fingerprinting · browser systems · honest uncertainty |
| **Fundi** | A local-first visual app studio where canvas edits and model edits converge on one validated specification, then export to code. | Local AI · product design · code generation |
| **Uwingi** | An experimental language and reasoning framework for contextual values, plural answers, and ternary truth. Currently an alpha foundation, not a production release. | Context · provenance · consent · deterministic execution |

Other explorations include accessible generative sound, evidence-bounded security tools, and bandwidth-aware systems.

## How we sustain

Most apps and sites are free to use. At this stage, **useful adoption matters more than collecting a tiny payment from each person**.

When recurring infrastructure creates real cost, such as compute, storage, bandwidth, voice, media relay, or third-party services, we charge only for the cost-bearing layer or seek institutional and sponsor support. The core path stays open wherever practical.

Traffic helps people discover the work. It is not the goal by itself. We care about useful adoption: people arrive, solve something, return, and help the work improve.

## Building is collaboration

Use it. Question it. Report what broke. Translate it. Document it. Design it. Code it. Or bring a problem worth solving.

Collaboration can begin before a pull request. **The more the merrier.**

## How we build

**Context before assumption** · **Rights before reach** · **Evidence before claims** · **Local-first when practical** · **Verification before release**

Accessibility, privacy, safety, rollback, and operational ownership are product features. Good design is not only how a system looks. It is how clearly the system behaves when reality gets complicated.
